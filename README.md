# 🐾 MeowRay — میو‌رِی

پنل VPN سبک و قابل‌حمل برای هاست‌های رایگان و محدود (KataBump، Railway و هر
هاست Node.js دیگر). MeowRay دور هستهٔ قدرتمند **vpn-ui ‏(نسخهٔ 1.9.4)** یک
رانر جاوااسکریپتی امن و کم‌مصرف می‌سازد: فقط با آپلود **دو فایل**
(`index.js` + `package.json`) و تنظیم چند متغیر محیطی، یک پنل کامل با
۹ اینباند، پورتال کاربری فارسی، لینک اشتراک و QR آماده است — بدون ساخت
دستی هیچ اینباندی.

## چرا MeowRay؟

- **مصرف کم:** سقف حافظهٔ سخت‌گیرانه برای هسته (GOMEMLIMIT/GOMAXPROCS)،
  تریم فایل‌های جغرافیایی (فقط ایران/روسیه)، و مصرف بیکار اندازه‌گیری‌شدهٔ
  حدود **۲۰۰ مگابایت** (در برابر ≈۵۲۷ مگابایت نسخهٔ مرجع).
- **قابل‌حمل (ضد بن):** همهٔ وضعیت در **یک پوشه** است. از پنل ادمین یک
  فایل بکاپ واحد (`tar.gz`) می‌گیرید؛ روی هاست جدید همان فایل را به‌صورت
  `restore.tar.gz` کنار فایل‌ها بگذارید — همه‌چیز (اینباندها، کاربرها،
  لینک‌های اشتراک) عیناً برمی‌گردد. بن شدن هاست = مهاجرت چنددقیقه‌ای، نه ساخت از صفر.
- **پورتال کاربری فارسی:** ورود، داشبورد اشتراک با لینک‌ها و QR، وضعیت
  ترافیک و انقضا — راست‌چین و تیره، بدون هیچ فونت یا CDN خارجی.
- **همگام‌سازی واقعی:** تغییر حجم/انقضا/فعال‌بودن کاربر از پورتال، روی
  کلاینت‌های موجود در اینباندها **اعمال** می‌شود (نه فقط کاربران بعدی).
- **امن به‌صورت پیش‌فرض:** ثبت‌نام بسته است؛ رمزها با scrypt هش می‌شوند؛
  متغیرهای محیطی به پردازهٔ پنل فقط از یک allowlist رد می‌شوند.
- **ناظر (Supervisor):** اگر پردازهٔ پنل بمیرد، با backoff خودکار بالا
  می‌آید و وضعیت سلامت از `/healthz` قابل بررسی است.

## نصب

### KataBump

۱. در پنل KataBump یک سرور Node.js بسازید.
۲. فایل‌های `index.js` و `package.json` را در ریشهٔ سرور آپلود کنید.
۳. متغیرهای محیطی (Environment) را تنظیم کنید — حداقل این‌ها:

| متغیر | مقدار پیشنهادی |
| :--- | :--- |
| `PANEL_HOST` | آدرس عمومی سرور (هاست‌نیم یا IP) — برای ساخت لینک‌های اشتراک |
| `MEOWRAY_ADMIN_PASSWORD` | یک رمز قوی برای ادمین (اختیاری؛ اگر ندهید، رمز تصادفی ساخته و فقط بار اول در لاگ چاپ می‌شود) |

۴. سرور را Start کنید. بار اول حدود ۳۳۰ مگابایت باینری دانلود می‌شود
   (یک‌بار)؛ بعد از آن بوت‌ها چند ثانیه‌ای‌اند.
۵. سرور رایگان KataBump هر ۴ روز نیاز به تمدید دارد — برای تمدید خودکار
   پوشهٔ `renew/` همین بسته را ببینید.

### Railway

۱. یک سرویس جدید بسازید و همین دو فایل را دیپلوی کنید (یا ریپو را وصل کنید).
۲. Railway خودش `PORT` را می‌دهد؛ MeowRay همان را استفاده می‌کند.
۳. برای آدرس عمومی: در Settings سرویس، یک **TCP Proxy** بسازید یا دامین
   عمومی بگیرید و مقدار `PANEL_HOST` را همان آدرس بگذارید.
   توجه: لینک‌های اشتراک باید به آدرس و پورتی اشاره کنند که از بیرون به
   سرویس می‌رسد؛ اگر از TCP Proxy استفاده می‌کنید، `PANEL_HOST` را
   `host:port` همان پروکسی بگذارید.

### هر هاست Node.js دیگر (VPS، کانتینر و…)

```bash
mkdir meowray && cd meowray
# index.js و package.json را اینجا بگذارید
PANEL_HOST=your.domain.or.ip MEOWRAY_ADMIN_PASSWORD='یک رمز قوی' node index.js
```

نیازمندی: Node.js ‏≥ 18 روی Linux x64. هیچ `npm install`ای لازم نیست
(وابستگی صفر — فقط کتابخانه‌های داخلی Node).

## آدرس‌ها

| مسیر | توضیح |
| :--- | :--- |
| `/` | پورتال کاربران (ورود، داشبورد اشتراک، QR) |
| `/kb/` | پنل مدیریت vpn-ui (همان UI اصلی Sanaei) |
| `/sub/<token>` | لینک اشتراک هر کاربر (base64) |
| `/healthz` | سلامت سیستم به‌صورت JSON |
| `/health` | صفحهٔ سلامت خوانا برای ادمین |
| `/admin` | مدیریت کاربران + دانلود بکاپ (نیازمند ورود ادمین) |

ورود ادمینِ پورتال با همان نام کاربری/رمز پنل انجام می‌شود.

## متغیرهای محیطی

| متغیر | پیش‌فرض | توضیح |
| :--- | :--- | :--- |
| `PORT` / `SERVER_PORT` | `8080` | پورت عمومی (تنها پورتی که از بیرون باز است) |
| `PANEL_HOST` | تشخیص خودکار IP | هاست‌نیم/IP عمومی برای لینک‌های اشتراک (می‌تواند `host:port` باشد) |
| `SERVER_IP` | — | جایگزین تشخیص خودکار IP |
| `PUBLIC_SCHEME` | `http` | `https` اگر جلوی سرویس TLS terminate می‌شود |
| `MEOWRAY_ADMIN_USER` | `admin` | نام کاربری ادمین (فقط بوت اول اعمال می‌شود) |
| `MEOWRAY_ADMIN_PASSWORD` | تصادفی | رمز ادمین؛ فقط در بوتِ اول اعمال می‌شود. روی نصبِ موجود، عوض‌کردن این متغیر رمز را عوض نمی‌کند (رمز داخل دیتابیس خود پنل ذخیره می‌شود و از بیرون قابل بازنشانی نیست)؛ مقدار متغیر فقط وقتی دقیقاً برابر رمز فعلی باشد به‌عنوان کاندیدای ورود امتحان می‌شود |
| `MEOWRAY_ROOT` | `./meowray-state` | پوشهٔ واحد وضعیت (باینری + دیتابیس + کاربران) |
| `REGISTRATION` | `closed` | ثبت‌نام پورتال: `closed` / `invite` / `open` |
| `MEOWRAY_INVITE_CODE` | — | کد دعوت وقتی `REGISTRATION=invite` است؛ اگر ست نشود، حالت invite همهٔ ثبت‌نام‌ها را رد می‌کند (fail-closed) |
| `USER_TRAFFIC_GB` | `10` | سقف ترافیک پیش‌فرض کاربر جدید (۰ = نامحدود) |
| `USER_EXPIRY_DAYS` | `30` | انقضای پیش‌فرض کاربر جدید (۰ = بدون انقضا) |
| `MEOWRAY_GOMEMLIMIT_MB` | خودکار | سقف حافظهٔ هسته (۰ = خودکار: ۶۰٪ سقف کانتینر یا ۱۹۲MB) |
| `MEOWRAY_RECONCILE_SEC` | `60` | فاصلهٔ همگام‌سازی کاربران با پنل (۰ = فقط دستی/رویدادی) |
| `MEOWRAY_RESTORE` | — | مسیر فایل بکاپ برای بازیابی در بوت |

## کاربران و اشتراک

- کاربر را از `/admin` (یا API) بسازید؛ MeowRay او را به‌صورت خودکار در
  هر ۷ اینباند کاربری (VLESS/VMess/Trojan روی TCP و WS، gRPC و
  HTTPUpgrade) به‌عنوان کلاینت می‌سازد. اینباند Shadowsocks و WireGuard
  اشتراکی‌اند (یک کانفیگ سراسری برای همه) و کلاینت per-user نمی‌گیرند —
  همان مدل نسخهٔ مرجع.
- هر کاربر یک لینک اشتراک (`/sub/<token>`) با **۶ کانفیگ** می‌گیرد.
  اینباند Shadowsocks و WireGuard سراسری‌اند و کانفیگ جدا نمی‌گیرند.
- تغییر حجم/انقضا یا غیرفعال‌کردن کاربر از همان صفحه، روی کلاینت‌های
  موجود اعمال می‌شود؛ کاربر منقضی یا غیرفعال در همگام‌سازی بعدی در پنل
  هم غیرفعال می‌شود.
- حذف کاربر = حذف کلاینت‌هایش از همهٔ اینباندها.

## بکاپ و مهاجرت به هاست جدید

**گرفتن بکاپ:** از `/admin` دکمهٔ دانلود بکاپ را بزنید (یا
`GET /api/admin/backup` با سشن ادمین)؛ یک فایل `meowray-backup-….tar.gz`
می‌گیرید که کل پوشهٔ وضعیت است. از خط فرمان هم می‌شود:

```bash
node index.js --backup ./meowray-backup.tar.gz
```

**بازیابی روی هاست جدید:**
۱. دو فایل `index.js` + `package.json` را آپلود کنید.
۲. فایل بکاپ را با نام **`restore.tar.gz`** کنارشان بگذارید (یا مسیرش را
   در `MEOWRAY_RESTORE` بدهید).
۳. سرویس را روشن کنید: MeowRay قبل از هر کاری وضعیت را بازیابی می‌کند،
   بعد بالا می‌آید. اینباندها، کاربرها و لینک‌های اشتراک دقیقاً مثل قبل‌اند.
۴. اگر فایل بکاپ خراب باشد، بازیابی **رد** می‌شود و سرویس با وضعیت قبلی/
   تازه بالا می‌آید — وضعیت سالم هرگز با فایل خراب جایگزین نمی‌شود.

## عیب‌یابی

| نشانه | راه‌حل |
| :--- | :--- |
| صفحهٔ «در حال آماده‌سازی» نمی‌رود | لاگ را ببینید؛ معمولاً دانلود بار اول (۳۳۰MB) هنوز تمام نشده یا `PANEL_HOST` قابل تشخیص نیست. خطای مهلک با پیام واضح در لاگ چاپ و پردازه خارج می‌شود تا هاست ری‌استارتش کند |
| خطای `internal panel port … already in use` | یک نمونهٔ دیگر MeowRay روی همان هاست در حال اجراست؛ قبلی را ببندید |
| لینک‌های اشتراک به آدرس اشتباه اشاره می‌کنند | `PANEL_HOST` را دقیقاً به آدرس:پورت عمومی‌ای بگذارید که کاربر به آن وصل می‌شود |
| رمز ادمین را فراموش کرده‌ام | رمز فعلی در فایل `state.json` داخل پوشهٔ وضعیت نگه داشته می‌شود (فیلد `panelPass`، با دسترسی ۰۶۰۰ — همان نسخه‌ای که رانر برای ورود خودکار لازم دارد)؛ آن را بردارید و با همان وارد شوید. راه آخر: حذف کامل پوشهٔ وضعیت و شروع تازه (همهٔ کاربرها و اینباندها پاک می‌شوند) |
| پنل مدام ری‌استارت می‌شود | `/healthz` فیلد `restarts` را نشان می‌دهد؛ لاگ پوشهٔ `log/` داخل پوشهٔ وضعیت را بررسی کنید؛ معمولاً کمبود RAM است: `MEOWRAY_GOMEMLIMIT_MB` را کمتر کنید |
| کاربر وصل نمی‌شود | در `/health` ببینید کاربر فعال است و منقضی نشده؛ همگام‌سازی را از `/admin` دستی اجرا کنید |
| روی KataBump جا کم است | پوشهٔ `backups/` داخل وضعیت را خالی کنید؛ بکاپ‌های قدیمی را نگه ندارید |

## توسعه و تست (برای توسعه‌دهنده)

```bash
npm test            # سلف‌تست داخل خود فایل (بدون بوت پنل)
node tests/unit.js  # تست‌های واحد
node tests/smoke.js # اسموک کامل بوت (دانلود واقعی + ری‌استارت + اندازه‌گیری مصرف)
```

## محدودیت‌های شناخته‌شده

- رمز ادمین پنل داخل دیتابیس خود vpn-ui نگه داشته می‌شود و از بیرون قابل
  بازنشانی نیست؛ MeowRay یک نسخهٔ آن را (فقط همان یک نسخه، با دسترسی
  فایل 0600 داخل پوشهٔ وضعیت) نگه می‌دارد تا بتواند وارد پنل شود.
- روی هر هاست فقط **یک** نمونهٔ MeowRay می‌تواند اجرا شود (پورت‌های داخلی
  ثابت‌اند)؛ برای چند سرور، چند کانتینر/سرویس جدا بگیرید.
